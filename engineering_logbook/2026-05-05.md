## Safety Wording Review

**Result**: PASS with one minor fix applied.

**Issue**: `docs/qnx_supervisor.md` — bullet "Certified to IEC 61508 SIL 3, ISO 26262 ASIL D (when properly qualified)" was ambiguous. Although the adjacent text clarified this was not applicable to the demonstrator, the bullet alone could be read as a project-level certification claim.

**Fix**: Reworded to "Certifiable to IEC 61508 SIL 3, ISO 26262 ASIL D as a product (requires qualified BSP and tool chain — NOT applicable to this Raspberry Pi demonstrator)".

**Conventions confirmed consistent across all files**:
- "ASIL-B-inspired monitoring path" — never "ASIL-B path" or "ASIL-B certified"
- "FFI-inspired architectural measures" — never "certified FFI"
- "demonstrator" — never "safety-certified system"
- "QNX-inspired supervisor" / "QNX supervisor (or Linux fallback)" — never unqualified "QNX system"
- Safety path is rule-based deterministic logic — AI/ML outputs never mentioned in safety decision path
