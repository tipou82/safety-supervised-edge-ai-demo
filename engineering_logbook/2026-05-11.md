## Camera-Based Hand Distance — Sensor Fusion (SYS-SAFE-012)

### Design

Supplementary SAFE_STATE trigger based on camera-estimated hand distance.
Uses pinhole model: `distance_m = (hand_width × focal_length) / bbox_width_px`

| Parameter | Value | Notes |
|---|---|---|
| FOCAL_LENGTH_PX | 480 | IMX708 estimate at 640×480 — requires calibration |
| HAND_REAL_WIDTH_M | 0.08m | Average adult hand width |
| CAMERA_SAFE_DISTANCE_M | 0.20m | Threshold — wider than ultrasonic (0.15m) |

**Wider threshold rationale**: camera distance has ±30% accuracy (AI-derived from MediaPipe bounding box). 0.20m provides safety margin over the 0.15m ultrasonic threshold.

### Architecture

```
hand_detection_node → estimates hand_distance_m from bbox width
object_detection_node → passes hand_distance_m through to /detections
decision_node → parses hand_distance_m → feeds camera_distance_m to StateEvaluator
StateEvaluator → if camera_valid AND camera_distance_m < 0.20m → SAFE_STATE
```

### New StateEvaluator rule (Rule 3, after ultrasonic critical_distance)

```cpp
if (in.camera_valid && in.camera_distance_m < CAMERA_SAFE_DISTANCE_M)
    → SAFE_STATE [camera_hand_critical]
```

`camera_valid=true` required — prevents spurious triggers when camera is offline.

### Safety boundary maintained

- AI output (bounding box) is used for distance estimation — documented as AI-derived
- Ultrasonic remains primary safety sensor (checked before camera in Rule 3)
- Camera trigger is supplementary only — does NOT replace ultrasonic path
- SYS-SAFE-012 added to system_requirements.md with explicit limitations

### Diagnostics

`/diagnostics` now includes `camera_distance_m` key:
- `no_hand` when no hand detected
- `0.185` (example) when hand within threshold

### Tests

6 new gtest cases added covering: trigger, boundary, camera_valid guard,
no-hand (FLT_MAX), far distance, ultrasonic priority over camera.

## Ultrasonic Debounce + Buzzer Improvements

### Issue: fast-moving object triggered false DEGRADED

**Problem**: single invalid ultrasonic reading (inf/out-of-range caused by acoustic
reflection loss when object passes quickly) immediately set `ultrasonic_valid=false`
→ DEGRADED → yellow LED + buzzer fired spuriously.

**Root cause**: `decision_node.cpp` called `ultrasonic_valid_ = false` on any single
invalid reading before the debounce fix.

**Fix 1 — ignore individual invalid readings**:
Valid readings reset the liveness timer; invalid readings are silently ignored.
`ultrasonic_valid` only cleared by the timeout — not by individual bad readings.

**Fix 2 — timeout 1s → 100ms**:
1s was too slow for sensor failure detection. 100ms = 2× the 50ms ultrasonic period:
- Tolerates 1 missed reading (transient acoustic miss) without triggering DEGRADED
- Detects true sensor failure within 100ms — matches SYS-SAFE-011 FTTI budget
- Matches proximity FTTI budget as secondary check

### Buzzer added to WARNING and DEGRADED states

`health_node` now drives GPIO 18 (active 3.3V buzzer):
- **OFF** in INIT, NORMAL, SAFE_STATE
- **ON** in WARNING (obstacle < 0.50m — audible proximity alert)
- **ON** in DEGRADED (sensor failure — audible fault indicator)

Yellow LED remains DEGRADED only. Buzzer covers both alert conditions.

### Final indicator mapping

| State | Green LED | Yellow LED | Buzzer | Red LED |
|---|---|---|---|---|
| INIT | ON | OFF | OFF | OFF |
| NORMAL | ON | OFF | OFF | OFF |
| WARNING | ON | OFF | ON | OFF |
| DEGRADED | ON | ON | ON | OFF |
| SAFE_STATE | OFF | OFF | OFF | ON |
