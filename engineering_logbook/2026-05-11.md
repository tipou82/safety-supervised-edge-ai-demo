## Camera-Based Hand Distance — Sensor Fusion (SYS-SAFE-012)

### Design

Supplementary SAFE_STATE trigger based on camera-estimated hand distance.
Uses pinhole model: `distance_m = (hand_width × focal_length) / bbox_width_px`

| Parameter | Value | Notes |
|---|---|---|
| FOCAL_LENGTH_PX | 480 | IMX708 estimate at 640×480 — requires calibration |
| HAND_REAL_WIDTH_M | 0.08m | Average adult hand width |
| CAMERA_SAFE_DISTANCE_M | 0.20m | Threshold — wider than ultrasonic (0.15m) |

**Wider threshold rationale**: camera distance has ±30% accuracy (AI-derived from MediaPipe bounding box). 0.20m provides safety margin over the 0.15m ultrasonic threshold.

### Architecture

```
hand_detection_node → estimates hand_distance_m from bbox width
object_detection_node → passes hand_distance_m through to /detections
decision_node → parses hand_distance_m → feeds camera_distance_m to StateEvaluator
StateEvaluator → if camera_valid AND camera_distance_m < 0.20m → SAFE_STATE
```

### New StateEvaluator rule (Rule 3, after ultrasonic critical_distance)

```cpp
if (in.camera_valid && in.camera_distance_m < CAMERA_SAFE_DISTANCE_M)
    → SAFE_STATE [camera_hand_critical]
```

`camera_valid=true` required — prevents spurious triggers when camera is offline.

### Safety boundary maintained

- AI output (bounding box) is used for distance estimation — documented as AI-derived
- Ultrasonic remains primary safety sensor (checked before camera in Rule 3)
- Camera trigger is supplementary only — does NOT replace ultrasonic path
- SYS-SAFE-012 added to system_requirements.md with explicit limitations

### Diagnostics

`/diagnostics` now includes `camera_distance_m` key:
- `no_hand` when no hand detected
- `0.185` (example) when hand within threshold
