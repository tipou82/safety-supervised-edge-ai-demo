## ROS2 Journey Summary

**Goal**: Install ROS2 on Pi5 to support M2 sensor pipeline development.

**What happened — four attempts before success:**

1. **Raspberry Pi OS Trixie (Debian 13) — no apt packages.**
   The packages.ros.org repository has no ROS2 entries for Bookworm/Trixie when using the
   standard Ubuntu-oriented setup. `apt-cache search ros-jazzy` returned nothing.

2. **Docker on Trixie considered — rejected.**
   Docker would run a Ubuntu 24.04 container natively on Pi5 ARM64 (no emulation, full MMU
   support). However, libcamera inside a Ubuntu 24.04 container cannot access the Raspberry Pi
   IPA modules from the RPi OS Trixie host kernel — the same camera incompatibility we already
   solved by leaving Ubuntu. Docker would have reintroduced it.

3. **Raspberry Pi OS Bookworm (Debian 12) — same apt problem.**
   Reflashed to Bookworm (Python 3.11, better ROS2 compatibility). Added packages.ros.org
   repository with "bookworm" codename. `apt update` succeeded but `apt-cache search ros-jazzy`
   and `ros-humble` returned only ROS1 packages from standard Debian repos. No ROS2 via apt.

4. **Ubuntu 22.04 considered — rejected on camera grounds.**
   Would have official ROS2 Humble apt packages. But Ubuntu ships upstream libcamera which
   lacks the Raspberry Pi IPA modules (`ipa_rpi_pisp.so`) needed for the IMX708. Same camera
   failure as Ubuntu 24.04. No Ubuntu version solves both camera and ROS2 simultaneously.

**Root cause of the conflict:**
- ROS2 via apt requires Ubuntu (22.04 for Humble, 24.04 for Jazzy)
- RPi Camera Module 3 (IMX708) requires Raspberry Pi OS (which ships RPi's libcamera fork)
- These are mutually exclusive via package manager

**Solution: Build ROS2 Humble from source on Raspberry Pi OS Bookworm.**
- Bookworm + Python 3.11 is a supported combination for Humble
- Camera works natively (rpicam-apps, libcamera 0.3.x with RPi IPA modules)
- ROS2 built from source with colcon — 287 packages, ~49 minutes on Pi5
- `ros2` CLI and `rclpy` verified working

## Architecture Decision — I2C Q&A Watchdog (replaces GPIO Heartbeat)

**Decision**: Replace the GPIO heartbeat (simple toggle on GPIO 17) with an I2C Q&A challenge/response watchdog between Pi5 (master) and Pi400 (slave at address `0x40`).

**Rationale**: A Q&A protocol provides stronger diagnostic coverage. A frozen or software-corrupted Pi5 process cannot generate a correct in-window response. A simple GPIO toggle could be sustained by stuck-at hardware with no software participation.

**Protocol summary**:
- Pi400 generates a 32-bit random seed (register `0x00`)
- Pi5 reads seed, computes `response = seed XOR 0xA5A5A5A5`, sends to register `0x01`
- Valid window: 50–100 ms after last correctly acknowledged response
- failure_counter: +1 on any failure; −1 after 2 consecutive correct; ≥3 → SAFE_STATE

**GPIO changes**:
- GPIO 17 stays permanently as Green LED (NORMAL indicator)
- GPIO 27 stays permanently as Yellow LED (DEGRADED indicator)
- E-stop: new dedicated wire, Pi400 GPIO 25 → Pi5 GPIO 25 (was TBD, now assigned)
- Red LED: wired-OR circuit (Pi5 GPIO 22 + Pi400 GPIO 22, each via 1N4148 + 150Ω) — Pi400 can assert SAFE_STATE red LED independently
